# DaedalusEngine V1.1.0

電力電子電路模擬器（Windows 11，Rust 原生程式）。
以網頁版「電力電子電路模擬器 V3.2.1」為參考重新實作，包含其全部元件模型，`.psimx` 電路檔兩邊通用。

名稱取自希臘神話中為伊卡洛斯打造羽翼的工匠代達洛斯（Daedalus）；圖示是代達洛斯打造的羽翼，下方是功率開關的 PWM 波形。

## 安裝與解除安裝

- 執行 `DaedalusEngine-Setup-V1.1.0.exe`。**不需要系統管理員權限**：程式安裝於
  `%LOCALAPPDATA%\Programs\DaedalusEngine`，捷徑與檔案關聯只寫入目前使用者（HKCU）。
- 安裝內容：`DaedalusEngine.exe`（圖形介面）、`daedalus-cli.exe`（命令列批次模擬）、`uninstall.exe`、本說明。
- **更新／修復**：已安裝時再執行安裝程式（或「設定 › 應用程式 › 已安裝的應用程式 › DaedalusEngine › 修改」）會進入維護畫面，
  依版本自動提供：
  - 安裝程式較新 → **更新**（建議）；
  - 版本相同 → **修復**：先檢查程式檔案（逐位元組比對）、開始功能表／桌面捷徑、.psimx 檔案關聯與登錄資訊，
    重新寫入後列出修復了哪些項目；
  - 安裝程式較舊 → **降級**（附警告）；
  - 以上皆可改選**解除安裝**。
  更新與修復沿用原本的桌面捷徑與檔案關聯選擇（可在畫面上變更），電路檔與使用者設定都保留。
- 解除安裝：「設定 › 應用程式 › 已安裝的應用程式 › DaedalusEngine › 解除安裝」，或執行安裝資料夾中的 `uninstall.exe`。
  使用者設定（`%APPDATA%\DaedalusEngine`）預設保留，可勾選一併刪除；您的 `.psimx` 電路檔不會被刪除。
- 安裝程式未經數位簽章，第一次執行時 Windows SmartScreen 可能顯示「Windows 已保護您的電腦」，
  請按「其他資訊 › 仍要執行」。

### 命令列（自動化部署）


`--repair` 會把檢查到並修復的項目逐行寫入紀錄。靜默模式的紀錄寫在 `%TEMP%\DaedalusEngine-Setup.log`，結束代碼 0 表示成功。

## 快速上手

1. 「檔案 › 範例」依分類開啟 32 個範例電路（電力轉換、三相系統、功率元件、變壓器與磁性元件、類比與控制 IC、
   被動電路與濾波、電源與受控源、控制方塊、數位邏輯、數位控制、分析功能），每個都附理論驗證（見「範例電路與驗證」）。
2. 按 **F5** 執行模擬；暫態結果顯示在波形視窗，AC 掃頻結果顯示在波德圖視窗（含交越頻率、相位邊限、增益邊限）。
3. 左側元件庫可依分類瀏覽或搜尋（中英文皆可），點選後在電路圖上左鍵放置；也可在空白處按 `/` 或雙擊快速新增。
4. **F7** 開啟模擬控制（時間步長、總時間、輸出設定、LTE 誤差控制等）。時間步長最小可設 1 fs。
5. 「模擬 › 參數掃描設定…」放置 Parameter Sweep 元件：指定參數檔中的一個變數（例如電感值填 `Lf`）與數值清單，
   F5 時每個數值各跑一次暫態，**以所有 CPU 核心平行運算**，同一探棒的各次結果疊在同一畫面（欄名如 `Vo [Lf=47µ]`）。
   此元件為 DaedalusEngine 新增，網頁版不認得。
6. 「模擬 › 蒙地卡羅分析設定…」放置 Monte Carlo 元件：每行一個參數檔變數與容差，例如
   `R1 5% gauss`（常態分佈，容差 = 3σ）、`C1 10% uniform`（±10 % 均勻分佈），再設定執行次數與亂數種子後按 F5。
   第 #0 次為標稱值，其餘各次以所有核心平行運算；波形視窗疊出全部結果，「模擬 › 蒙地卡羅統計結果」列出每個探棒
   末值／平均／最大／最小的平均值、σ、最小、最大與每次的抽樣值，可匯出 CSV。相同種子可完全重現。
   此元件亦為 DaedalusEngine 新增（範例「蒙地卡羅容差分析」）。

### 硬體加速

- 繪圖：電路圖與波形以 GPU（OpenGL）繪製；「模擬 › 硬體加速」可看到使用中的 GPU。
- 運算：AC 小訊號注入掃頻與參數掃描把各頻率點／各掃描值分配給所有 CPU 核心（可在同一選單限制執行緒數）。
  例：監控電路 14 個掃描值，1 核心 2.49 s → 14 核心 0.44 s。
- 單次暫態模擬的每一步都依賴上一步，矩陣只有數十到數百階，在 CPU 上每步約 1 µs；
  交給 GPU 時單是資料往返就要 5～20 µs，且精度需要雙精度浮點（內顯幾乎不支援），因此不使用 GPU 解矩陣
  （PSIM、SIMetrix、LTspice 亦同）。實測 AVX2 向量指令版本也沒有可量測的加速，故維持通用版本。

## 模擬引擎

- 修正節點分析（MNA）＋稀疏 LU（Markowitz 排序、門檻選主元、符號分解重用、迭代精修）。
- 梯形積分；切換後以兩個後向尤拉小步阻尼數值振盪；開關切換瞬間以割線法內插定位；
  區域截斷誤差（LTE）自動減半步長；斷點對齊（PWM 邊緣、步階、PWL 轉折）。
- 非線性元件：牛頓法＋SPICE `pnjlim` 限制；Level-1 二極體、Gummel-Poon BJT、Shichman-Hodges MOSFET
  （非線性 Cgd/Cds）、LM393、TL431、光耦合器、含閘極驅動的非理想 MOSFET/IGBT。
- 控制方塊：依資料相依排程，代數迴路以 Tarjan SCC 偵測後用 Gauss-Seidel／牛頓法求解；C 語言方塊以內建直譯器執行。
- AC 分析：注入法（時域模擬＋傅立葉擷取，各頻率點平行運算）與線性頻域法。

### 高精度模式（自動選步長）

Simulation Control 的「高精度模式」設為 1、填入目標誤差（預設 1e-6，相對於各探棒滿刻度）後：
以 dt 與 dt/2 平行模擬，用步長加倍法估計全域誤差；未達目標就依梯形法 dt² 誤差律自動再細分（每次 2～4 倍），
達標後輸出 Richardson 外插結果。結束時狀態列顯示最終步長與估計誤差；若電路含極快的切換邊緣、
或步長小到雙精度浮點無法再改善（ps 級步長配 nH／pF 元件時矩陣條件數隨 1/h² 惡化），會停在最佳層並說明。

| 範例（目標 1e-6） | 最終步長 | 估計誤差 | 對精確解的實際誤差 | 時間 |
|---|---|---|---|---|
| Buck（理想開關） | dt/2 | 2.1e-7 | 1.5e-7 | 約 15 ms |
| RLC | dt/4 | 4.7e-7 | 6.7e-10 | 約 30 ms |
| 橋式整流 | dt/8 | 7.2e-7 | 2.3e-7 | 約 50 ms |
| TL431 光耦 | dt/16 | 3.2e-7 | — | 約 0.5 s |
| 雙脈衝（ns 邊緣） | dt/8 | 2.6e-3（數值極限） | — | 約 4 s |
| 監控電路（比較器邊緣） | dt/8 | 1.6e-3（邊緣主導） | — | 約 7 s |

含 ns 級切換邊緣的電路以「逐點」誤差衡量會被邊緣時間的微小偏移主導；以邊緣時間衡量，
雙脈衝 dt/8 時為 0.5 ps、監控電路為 1.3 ns（約其 ms 時間尺度的 1e-6）。

### 半導體模型驗證

- **SPICE 方程式**（`node tools/spice_check.js`，需 `tools/ngspice`）：同一組模型卡在 ngspice 47 與本程式跑相同電路——
  二極體／齊納／LED、BJT 輸出與 Gummel 曲線、MOSFET Level-1 的靜態特性相差 1e-6～1e-8；
  MOSFET 開關暫態 1.7e-5、BJT 開關 2.3e-4（ngspice 本身收斂誤差內）；1N4148 反向恢復截止邊緣相差 2～10 ps（儲存時間 0.1 %）。
- **預設元件對資料手冊**（`node tools/datasheet_check.js`，Vishay／onsemi 規格）：37 項全部在規格內
  （hFE、VCE(sat)、VBE(sat)、VF、CD、CJ、IR、V(BR)、trr）。
- **行為模型**（`node tools/behav_check.js`）：TL431、LM393、光耦、非理想 MOSFET、資料手冊參數二極體以資料手冊測試電路量測，
  16 項全部重現所輸入的規格值（Vref 2.495 V、Zka 0.202 Ω、VOL、ISINK、tpd、CTR、Rds(on)、Coss、Cj、儲存時間、Qrr 等）。
- 資料手冊參數二極體可填「di/dt Qrr 的測試條件」：依電荷控制模型反算 TT，使該 di/dt 下抽出的恢復電荷等於 Qrr
  （200 A/µs 測試：409 nC 對 400 nC）；未填時沿用 TT = Qrr / Irr，在有限 di/dt 下抽出電荷會明顯偏少（同條件僅 49 nC）。
- 模型假設：TL431 飽和時 Vka 約 1.4 V（資料手冊未規定）。

### 準確度驗證

1. **與理論／獨立解析解比對**（`bash tools/verify.sh` 一次重跑 1、2 兩項）：
   以矩陣指數精確分段解（不共用模擬器程式碼）比對範例波形——Buck 全程 Vo 最大相對誤差 2.6e-6、
   RLC 9e-6、橋式整流 1.5e-5（0.6 s 全程）；穩態 Vo = D·Vin（43.6999 V 對 43.7 V）、IL 漣波、
   RLC 穩態振幅 |H(jω)| 六位數一致；RLC 波德圖與解析轉移函數相差 1e-14 dB；
   Buck 注入法掃頻 5 kHz 以下與平均模型相差 < 0.004 dB / 0.013°；
   雙脈衝的 RL 充電、米勒平台電荷 = Qgd、反向恢復 Irr 與 Qrr·di/dt 一致；監控電路 RC 時間常數 7.5045 ms 對 7.5062 ms。
2. **皮秒時間精度**：τ = 10 ps 的 RC 以 1 ps 步長模擬，等效時間誤差 0.036 ps；
   10 GHz LC 振盪 20 週期後相位誤差 0.65 ps（步長 0.25 ps 時 0.04 ps）；
   t ≈ 1 ms 處比較器切換時刻的定位誤差 0.002～0.006 ps（步長 1～10 ns 皆同）。
3. **與網頁版原始 JavaScript 引擎逐點比對**（`bash tools/regress.sh`）：7 個範例與 18 組回歸案例
   （涵蓋全部 215 種可模擬元件）相對誤差約 1e-9（下列刻意修正處除外；每一處都另以理論、平均模型或
   細步長參考解確認，腳本會列出原因）；
   速度約為網頁版 3～20 倍（Buck 範例 6 ms 對 55 ms；Buck AC 掃頻 0.35 s 對 7.7 s）。

### 與網頁版的差異（刻意修正）

- AC 線性分析中電流感測器（ISEN）被重複蓋印，導致增益錯誤 → 已修正（結果與網頁版相差 2 倍，屬預期）。
- 帶電流感測的電容器在初始條件求解時的處理錯誤 → 已修正。
- 殘差計算在稀疏樣式變動後可能產生 NaN → 已修正；初始條件求解每次使用新的 LU 分解。
- AC 注入法每個頻率點都從完整狀態快照開始，結果與執行緒數無關、可重現。
- C 方塊：邏輯運算結果為 0/1、`round` 依 C 語意、`static` 區域變數跨步保留、未初始化變數為 0，
  語法錯誤在編譯時即回報。
- 離散積分器（IntD）的範圍折返加入防止無窮迴圈的保護。
- 非理想 MOSFET／IGBT 的非線性米勒電容 Cgd：原版把電容轉折放在 Vgd = 0，使關斷米勒平台多吸收
  線性區的大電容電荷（平台約為 Qgd/Ig 的 1.5 倍）。轉折改在通道夾止點 Vgd = Vth（飽和／線性區交界），
  平台電荷因此等於資料手冊 Qgd（雙脈衝範例 16.0 nC 對 15 nC）。
- 時間步長下限由 1 ps 降為 1 fs；事件時間容許值不低於總時間的雙精度解析度，長時間細步長模擬也能精確對齊。
- 牛頓迭代在極小步長時會因矩陣條件數惡化而在捨入雜訊中來回振盪、被誤判為不收斂（原版亦同）：
  停滯判斷改為「兩次迭代內沒有實質進展且已遠小於訊號」即視為收斂（一般步長的結果不變）。
- 預設模型卡依原廠資料手冊修正：1N4007 BV 1000 → 1100 V（額定 1000 V 時漏電 ≤ 5 µA）、CJO 10 → 39 pF（4 V 時 15 pF）；
  1N5819 CJO 110 → 259 pF（4 V 時 110 pF）；2N4401 RB 10 → 4.7 Ω（VBE(sat) 0.85 V @ 150/15 mA、1.06 V @ 500/50 mA）。
- 編輯器會自動合併同一直線上相連的導線。
- **V1.0.0 新增修正**（以新範例的理論驗證找出）：
  - 訊號源在步長終點 t 精確取值，只在 t 恰為跳變點時取單側極限（兩點外插，對步階／方波／鋸齒／PWL 精確）。
    原版一律取 t ± ε/2，使平滑波形帶有約 1e-9 的系統誤差；修正後訊號源波形誤差在 1e-12 以下。
  - 以上修正後，回歸案例 ac_inject（Buck 閉迴路 AC 注入掃頻）在 10.36 kHz 的點對平均模型的誤差
    由網頁版的 35.6 % 降為 0.78 %（其餘頻率點兩者相同，約 0.1～0.4 %）。
  - 時間延遲方塊（TDELAY）多延遲一個步長 → 已修正。
  - 非線性受控源（乘、除、平方根、冪次）在 t = 0 的工作點未求解（輸出 0）→ 已納入初始牛頓迭代。
  - 電流控制電壓／電流源尋找控制支路時把各個接地符號視為不同節點 → 已修正。
  - 交流電表的 RMS 改為一週期內 √(⟨u²⟩ − ⟨u⟩²) 的精確值（原高通濾波法使讀值偏低約 1.9 %）。
  - 電源的斜率轉折點（三角波頂點、PWL 轉折、斜坡步階）與飽和電感換段後，下一步以後向尤拉重新起步（同 SPICE），
    消除梯形法在代數電壓上不衰減的振鈴；代價是轉折處局部誤差略增（1e-5 級，與步長誤差同量級）。
  - A/D 轉換器在輸入恰為量化門檻時（例如 2.5 V／5 V × 256 = 128）與量化方塊一樣不受 1 ulp 捨入雜訊影響。
  - 堆疊（STACK）說明更正為「輸出 = 目前堆疊頂端值」（行為與網頁版相同）。
  - 參數掃描／蒙地卡羅結果超過 12 條曲線時，波形圖內圖例改為摘要（左側清單仍逐條列出）。
- **V1.0.1**：新增第 25 個驗證範例「迴路增益量測」，元件涵蓋率達 100 %；
  迴路探棒（ACP2）極性設 0 時量測的是 H = V(x)/V(•)，波德圖不再把它標成「迴路增益」並計算相位裕度，
  改報 0 dB 穿越與 −3 dB 頻寬（極性 1 的迴路增益不變，計算結果不受影響）。

## 版本規則

版本號為 `V主.次.修`：

- 修正錯誤或微幅修改 → 第三碼＋1（例：V1.0.0 → V1.0.1）；
- 新增功能 → 第二碼＋1，第三碼歸零（例：V1.0.3 → V1.1.0）；
- 大改版 → 第一碼＋1，後兩碼歸零（例：V1.4.2 → V2.0.0）。

## 從原始碼建置（開發者）

需求：Rust（stable, MSVC）與 Visual Studio 2022 Build Tools（C++ 工具組）。

```
cargo build --release -p daedalus-app            # 圖形介面
cargo test -p daedalus-core                       # 單元測試
bash tools/regress.sh                             # 與 JS 參考引擎交叉驗證（需要 Node.js）
bash tools/verify.sh                              # 範例對理論、AC 掃頻、皮秒精度
node tools/examples/gen.js                        # 由 defs*.js 產生 25 個驗證範例
node tools/examples/verify.js                     # 執行並比對全部範例（263 項，AC 範例自動加 --ac）
node tools/examples/coverage.js -m                # 範例的元件涵蓋率
powershell -ExecutionPolicy Bypass -File tools\package.ps1   # 產生 dist\DaedalusEngine-Setup-V1.1.0.exe
```

專案結構：`crates/daedalus-core`（模擬引擎）、`daedalus-app`（GUI）、`daedalus-cli`（命令列）、
`daedalus-installer`（安裝程式）、`daedalus-icongen`（由 `assets/icon.svg` 產生圖示）；
`reference/` 為網頁版原始碼與比對用的 Node 腳本。

`tools/spice_check.js` 需要 ngspice（僅測試用，不隨程式發布）：從
<https://sourceforge.net/projects/ngspice/files/ng-spice-rework/47/> 下載 `ngspice-47_64.7z`，解壓縮到 `tools/ngspice`。

正式版由 GitHub Actions（`.github/workflows/build.yml`）建置、測試並簽章，步驟見 [docs/signpath-setup.md](docs/signpath-setup.md)。
